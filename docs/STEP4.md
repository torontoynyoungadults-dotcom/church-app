## 2. 데이터 흐름

**필기 한 글자**: 글자 → (가벼운 일) 글 저장(메모리) + 타이머 다시 걸기 + 글자 수 → 0.3초 뒤 이 기기 임시 보관(localStorage) → 입력 멈춘 지 1초 → `sermonNoteSave(token, note, baseVersion)`.

**서버**: `sermonNoteSave` 는 시트에 바로 쓰지 않고 **메모리 버퍼**(`lib/notes-buffer.js`)에 담고 곧바로 "저장됨"을 답합니다. 4초마다 바뀐 노트를 모아 `설교노트` 탭에 **한 번에** 씁니다(같은 노트가 여러 번 바뀌어도 마지막 것만). 서버 종료(SIGTERM · 배포)에서도 남은 것을 모두 씁니다. 시트 쓰기가 실패하면 버퍼에 남겨 두고 점점 길게 재시도합니다.

> **왜 버퍼?** 구글 시트를 부르는 다리(`bridge`)는 동기식이라 시트에 한 번 쓰는 동안 서버 전체가 멈춥니다(Step 3 §5). 주일 예배 중 여럿이 필기하면 초당 여러 번 서버가 멈춥니다.

**AI**: `POST /api/sermonNoteRefine` 는 `server.js` 의 **비동기 경로**입니다. 로그인 · 한도 · 프롬프트는 `sermonNoteRefinePrep_`, 제미나이 호출은 `lib/notes-ai.js`(비동기 fetch), 마무리는 `sermonNoteRefineDone_`. 답을 기다리는 몇 초 동안에도 다른 사람의 저장 · 화면이 그대로 처리됩니다(기존 AI 기능은 그 시간 동안 서버가 멈춤). 사용자당 4초 간격 · 하루 40번, 한 번에 12,000자, 노트는 `<노트>` 구분자로 감싸 프롬프트 주입 방어, 원문에 없는 내용은 만들지 않도록 지시, 결과는 **미리 보고 고름**(자동으로 덮어쓰지 않음).

## 3. 새 시트 · 서버 함수 (모두 `logic/notes.js`)

`설교노트` 탭(주보 워크북에 자동 생성, `lib/db.js` 에 등록): `ID · 이름 · 날짜 · 제목 · 성경본문 · 설교자 · 필기 · 묵상적용 · 묵상날짜 · 묵상구절 · 출처 · 버전 · 만든시각 · 수정시각 · 삭제`.

| 함수 | 설명 |
|------|------|
| `sermonMeta(date)` | (로그인 없이) 게시된 주보의 설교 정보 |
| `sermonNotesInit(token)` | 내 노트 목록 + 주보 정보(최근 8주) + 오늘의 묵상 + AI 상태 |
| `sermonNoteGet` · `sermonNoteByDate` | 노트 열기 · 그 주일의 주보 필기 |
| `sermonNoteSave(token, note, baseVersion)` | 저장(버전 · 충돌 · 재전송 안전) |
| `sermonNoteDelete(token, id, restore)` | 지우기/되살리기(줄을 지우지 않고 표시만) |
| `sermonNoteLink(token, id, date, verse)` | 오늘의 묵상에 연결/해제 |
| `devotionNotes(token, date, verse)` | 묵상 화면용: 연결된 노트 + 연결할 수 있는 최근 노트 |
| `sermonNoteRefine(token, text, mode, ctx)` | AI 정제(`polish` / `structure`) |

## 4. 글을 잃지 않는 장치

- **내 것만**: 노트는 주인만 읽고 쓸 수 있습니다(관리자키로도 못 봄). 다른 사람이 노트 번호를 알아도 열 수 없고, 쓰기 단계에서도 다른 사람 줄을 덮어쓰지 않습니다.
- **버전 충돌**: 저장 요청에 "내가 아는 서버 버전"을 실어 보내고, 그 사이 다른 기기가 고쳤으면 **덮어쓰지 않고** 알립니다 → "둘 다 보관(내 글은 '충돌 사본' 노트로)" / "이 화면 글로 덮어쓰기" / "다른 기기 글 쓰기". 응답을 못 받아 같은 저장을 다시 보내면(내용이 같으면) 이미 저장된 것으로 처리. 다른 기기에서 지운 노트는 조용히 되살리지 않고 묻습니다. 같은 주일의 주보 필기가 이미 있으면 이어 붙이기.
- **서버가 최근 몇 초를 잃은 경우**(버퍼에 있을 때 갑자기 종료): 화면이 "서버가 확인해 준 버전"을 함께 기억해 두었다가, 다음에 열 때 서버가 더 오래된 것을 알아채고 이 기기의 글로 다시 저장합니다.
- **끊김 · 창 닫힘**: 인터넷이 끊겨도 계속 쓸 수 있고(이 기기에 보관, 돌아오면 자동 저장), 창을 닫는 순간에도 임시본을 쓰고 서버에 한 번 더 보냅니다. 못 보낸 임시본은 오래돼도 지우지 않고 노트 목록에 "이 기기에만 · 전송 대기"로 보입니다.
- **로그인 없이 · 만료된 로그인**: 주보 필기 창은 그래도 열려서 이 기기에 저장하고, 로그인하면 계정으로 보냅니다(같은 주일 필기가 이미 있으면 뒤에 이어 붙임).
- **시트 안전 저장**: 구글 시트는 `=`, `+`, `-`, `@` 로 시작하는 글을 수식으로, 숫자/날짜 모양 글을 숫자/날짜로 바꿔 버립니다(설교 필기에 "- 첫째" 처럼 자주 등장). 모든 글 칸 앞에 눈에 안 보이는 표시(U+200B)를 붙여 저장하고 읽을 때 한 번 뗍니다.

## 5. 화면 성능 · 반응형

- 글자 하나당 하는 일이 매우 적음 — **2만 9천 자 글에서 글자 하나 평균 0.22ms**(시험 기준 1ms 미만). 입력칸은 자동 늘어남 없이 고정 높이 + 내부 스크롤(긴 글에서 리플로 없음).
- 한글 조합(IME) 중에는 글을 건드리지 않고, 목록 이어쓰기(`- ` 에서 Enter)는 조합이 끝난 Enter 에만. 글 삽입은 `execCommand('insertText')` 라 브라우저 **실행 취소(⌘Z)** 가 그대로 됩니다.
- 키보드가 올라오면 `visualViewport` 로 보이는 높이를 따라가서 **서식 막대가 키보드 바로 위에 붙어** 있습니다(가려지지 않음). 서식 막대를 눌러도 키보드가 내려가지 않음.
- 폰: 목록 → 편집(전체 화면) / 900px 이상: 왼쪽 목록 + 오른쪽 편집. 어두운 유리(Dark Glassmorphism) + 주황 강조, 글씨는 흰색(대비 7:1 이상), 입력칸 글씨는 순백. `prefers-reduced-motion` 존중.

## 8. 배포 · 확인

1. `git push` → Render 자동 배포. 환경변수 추가 없음(AI 는 기존 `GEMINI_API_KEY` 와 "AI 켜짐" 설정을 그대로 사용).
2. 첫 저장 때 `설교노트` 탭이 주보 워크북에 자동 생성됩니다.
3. 정적 파일(`public/notes/*`)은 1시간 캐시되므로 나중에 고치면 `?v=` 숫자를 올려 주세요(`Notes.html` · `Bulletin.html`).

## 9. 알아 둘 한계

- 시험은 **가짜 구글(FakeGoogle)** · 가짜 제미나이 답으로 했습니다. 실제 구글의 속도와 제미나이 결과 품질은 배포 후 확인이 필요합니다.
- "몇 초에 한 번 시트에 씀"이라, 서버가 갑자기 죽으면 마지막 몇 초는 서버에 없을 수 있습니다 — 이 경우 화면이 다음에 노트를 열 때 이 기기의 글로 복구합니다(다른 기기에서만 보던 경우엔 그 몇 초치는 복구되지 않음).
- 실제 폰 키보드(iOS/Android)의 동작은 크롬으로 흉내 낸 것입니다(화면 높이 변화 · IME 조합 이벤트). 아이폰에서 한 번 직접 눌러 보시길 권합니다.
- "AI 정리"는 원문에 없는 내용을 만들지 않도록 지시했지만 AI 이므로 **미리 보기에서 확인 후 적용**하도록 했습니다(결과 길이가 크게 달라지면 경고).
- `Portal.html` 글씨 수정은 "내 정보 수정"(브라우저 실측 확인)과 같은 방식으로 셀 신청 · 양식 화면(`#caWrap` · `#fmWrap`)에도 적용했지만, 이 두 화면은 시험 자료에서 입력칸이 열리지 않아 실측하지 못했습니다.
