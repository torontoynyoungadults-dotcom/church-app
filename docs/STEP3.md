# Step 3 — 회계(환급 · 행사 예산/정산) · 제자훈련 단일 원천 · 속도 개선

> 원칙: 운영 중인 앱이므로 **기존 기능은 그대로 두고 덧붙이거나, 안쪽만 바꿨습니다.** 새 서버 코드는 `logic/` 의 새 파일로 분리했고(`lib/runtime.js` 의 `EXTRA_FILES` 로 `app.js` 뒤에 이어 붙임), 새 화면 스크립트는 `public/budget/` 에 따로 있습니다.
> 열쇠 표기: 이 앱의 교적에는 회원번호(Member ID) 칸이 **없고** 셀원명단 · 사역팀원 · 제자훈련명단이 모두 **이름**으로 이어져 있습니다. 그래서 "Member ID 조회"는 **이름 조회**로 구현했고, 열쇠를 만드는 자리를 `훈련키_()` 한 곳으로 모았습니다(나중에 회원번호가 생기면 이 함수만 바꾸면 됩니다).

## 2. 데이터 흐름

**환급신청서**  포털 로그인 → `getExpenseApplicant` → 화면 자동 입력 → `submitExpense` → `지출`(머리) + `지출항목`(영수증 줄, 각 줄에 지출일) → 회계팀 승인 · 지급 → (행사 이름을 "예산"에 지정한 건은) 행사 화면 [환급신청서 가져오기]로 **영수증 줄 하나 = 거래 한 건**(날짜 = 그 줄의 지출일). 가져온 줄은 `지출신청번호(EXP-…#2)`가 붙어 **다시 가져와도 중복되지 않습니다.**

**행사 예산**  `행사예산`(머리 · 상태 · **버전**) ← `행사예산항목`(예산 줄) ← `행사거래`(실제 거래) → 집계(항목별 O(항목+거래) 해시) → 정산 확정 시 `행사정산` 에 **그 순간의 스냅샷(JSON)** 저장, 상태 = 정산완료(거래 · 예산 잠김, 정산 권한자가 사유를 적어 다시 열 수 있음). 모든 변경은 `행사이력` 에 남습니다.

**엑셀**  화면(브라우저)이 엑셀 파일을 만들고 읽어 JSON 으로 바꿈 → 서버는 JSON 만 받아 **검증 → 미리보기 → 적용(잠금 안에서 전부 또는 아무것도)**. 서버에 엑셀 라이브러리가 필요 없습니다.

**제자훈련**  `프로필/셀원목록` → `훈련키_(이름)` → `훈련현황맵_()`(시트 3장을 **한 번** 읽어 이름 → 현황 해시 맵) → 필요한 사람만 O(1) 조회. 요청 안에서 캐시되고 시트를 고치면(`캐시비움_`) 비워집니다.

## 3. 권한 (행사 회계)

| 등급 | 할 수 있는 일 |
|------|--------------|
| 조회 | 보기 · 엑셀/PDF 내려받기 |
| 입력 | 거래 기록/수정/삭제 · 엑셀 올리기(거래) · 환급신청서 가져오기 |
| 정산 | 정산 확정 · 다시 열기 |
| 관리 | 행사 만들기 · 예산 항목 · 접근 권한 주기 |

- 관리자키 · 회계팀 키 · 회계 권한 팀 계정 = 모든 행사 **관리**. **커미티 · 회계팀 역할은 기본 "조회"** (더 높이려면 [접근 권한]에서).
- 화면은 버튼을 숨기기만 하고, **모든 서버 함수가 요청마다 등급을 다시 확인**합니다. 자기 자신의 관리 권한은 스스로 낮출 수 없습니다. "모든 행사" 권한은 관리자/회계팀 키만 정할 수 있습니다.

## 4. 새 시트 (finance 워크북에 자동 생성)
`행사예산` · `행사예산항목` · `행사거래` · `행사정산` · `행사이력` (`lib/db.js` 에 등록, 11개 시트 구조 그대로). 옛 단일 시트 모드에서는 같은 문서 안에 탭으로 생깁니다. `지출항목` 시트에는 `지출일` 열, `제자훈련명단` 에는 옛 기록용 열 2개(`이전상태` · `이전출석`)가 첫 사용 때 자동 추가됩니다.

## 5. 속도 — getMyProfile 14초의 원인과 고친 것
**원인**: 서버가 구글 시트를 읽는 다리(`bridge`)는 **동기식이라 읽는 동안 서버 전체가 멈춥니다.** 프로필 하나를 만들 때 탭 하나하나(교적 · 셀원 · 사역 · 출결 · 제자훈련…)를 **따로 여러 번** 읽었고, 같은 탭을 요청 안에서 반복해 읽는 곳도 있었습니다. 읽기 1회에 수백 ms × 수십 회 = 14초.

| 고침 | 효과 |
|------|------|
| **한꺼번에 읽기(batch)** — 작은 탭은 묶어서 한 번 호출(`SHEET_EAGER_CELLS`), 포털에 필요한 탭은 미리 읽기(`포털탭_`) | API 호출 수십 회 → 4회 |
| **해시 맵** — `교적맵_`, `훈련현황맵_` 로 이름 → 값을 O(1) 조회 (이중 반복문 제거) | 사람 수에 거의 무관 |
| **서버 캐시** — 앱 메모리(`Book`)가 캐시. 시트를 고칠 때만 `캐시비움_()`. (Apps Script 의 PropertiesService/CacheService 는 필요 없음: 이 서버는 계속 떠 있는 Node 라서 메모리가 곧 캐시) | 두 번째부터 ~65 ms |
| **서버 웜업** — 시작 직후 포털 탭을 미리 읽음(`웜업_`) | 첫 사용자도 빠름 |
| **브라우저 캐시** — 화면 자료를 `sessionStorage` 에 저장 → 다시 열면 **저장된 화면을 먼저 그리고**, 뒤에서 새로 받아 바꿈(로그아웃/토큰 만료 시 삭제 · 15분 만료) | 체감 즉시 |
| **느린 요청 로그** `[느림]` (기본 1.5초 넘으면) | 앞으로 병목을 바로 찾음 |

시뮬레이션(호출당 지연 250 ms): 첫 호출 6.5초 → **1.7초**, 이후 158 ms → **65 ms**. ※ 실제 구글에서의 수치는 배포 후 확인이 필요합니다. Render 무료 서버가 잠들었다 깰 때의 첫 접속(수십 초)은 코드로 못 줄이므로 외부 keep-alive(`/healthz` 를 5~10분마다 호출)를 권합니다.

## 6. 기존 기능은 어떻게 보존되나
- 기존 API 이름 · 시트 · 열 순서 그대로. 새 열은 **뒤에 덧붙임**, 없으면 자동 추가.
- 옛 지출신청서(항목에 날짜 없음)는 예전 지출일로 표시. 옛 헤더 지출일도 계속 채워짐.
- 제자훈련: **옮기기 전까지는 교적의 옛 값을 예비로 읽음** → 화면이 갑자기 비지 않음. 교적 저장은 제자훈련 칸을 건드리지 않음.
- 회계 권한은 기존 `사용자권한` 표에 `구분=회계` 줄로만 추가 — 다른 권한 줄에 영향 없음.

## 7. 제자훈련 옮기기 (한 번만, 커미티/관리자)
1. `discipleshipMigrationStatus(관리자키)` — 교적에만 적혀 있는 사람 수/샘플 확인
2. `discipleshipMigrate(관리자키, false)` — 제자훈련명단(기수=LEGACY)으로 복사. 몇 번 실행해도 중복 없음
3. 확인 후 `discipleshipMigrate(관리자키, true)` — 교적의 옛 제자훈련 칸 비우기 (한 곳에만 남김)

## 8. 배포 · 확인
1. `git push` → Render 자동 배포. 환경변수 추가 없음.
2. 첫 실행 때 새 탭이 자동 생성됩니다. `/?page=budget&key=<관리자키>` 로 행사 화면 열기(포털 메뉴 "행사 예산"은 회계 권한이 있는 사람에게만 보임).
3. `npm run test:step3` — 서버 198 + 포털 8 + 예산 화면 37 항목 (`test:step1` · `test:step2` 도 그대로 통과).

## 9. 알아 둘 한계
- 시험은 **가짜 구글(FakeGoogle)** 로 했습니다. 실제 구글 계정에서의 속도와 "HTML → PDF 변환"은 배포 후 확인이 필요합니다(PDF 는 실패해도 인쇄 화면으로 대체).
- 한 번에 엑셀 3,000줄까지. 정산 스냅샷은 셀 한도 때문에 매우 큰 행사에서는 항목 요약만 저장합니다.
- 헤드리스 크롬 시험에서는 한글 파일명이 `download` 로 보고되지만, 실제 크롬은 정상 이름으로 저장합니다.
