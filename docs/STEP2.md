# Step 2 — 찬양·방송팀 허브 (연습 모드 · 실시간 필기 · 송폼 · 메트로놈 · 음정 · 가사 · 통계)

> 원칙: 이미 운영 중인 앱이므로 **기존 기능은 지우거나 바꾸지 않고**, 새 기능을 "덧붙이는" 방식으로 만들었습니다.
> 새 스크립트는 모두 `defer` 로 불러오므로, 어느 하나가 실패해도 예전 찬양 화면은 그대로 동작합니다.

## 2. 바뀐 파일 / 새 파일

**새 파일 (public/worship/)**: `practice.js` (뷰어) · `practice-panels.js` (탭 6개) · `anno.js` (필기 엔진) · `rt.js` (실시간 연결) · `metro.js` · `formb.js` · `pitch.js` · `lyrics.js` · `stats.js` · `hub.css`
**새 서버 파일**: `lib/realtime.js` (Socket.io 방 · 리더 · 필기 검증/저장) · `logic/worship2.js` (필기 불러오기/저장, 실시간 인증)
**고친 기존 파일**: `views/Worship.html` (스크립트 연결 · 연습 버튼 · 송폼 만들기 · 통계 팝업 호출 부분만) · `server.js` (Socket.io 붙이기, `/sheet/:id`, 종료 시 저장) · `lib/db.js` (`찬양주석` 탭 정의) · `lib/runtime.js` (worship2 로드) · `package.json` (socket.io)
**시험**: `scripts/test-step2-server.js` · `test-step2-client.js` · `test-step2-more.js` · `scripts/browser/*` (진짜 크롬 시험)

## 3. 기존 기능은 어떻게 보존되나
- 기존 API · 시트 · 열 이름은 그대로. 새 데이터는 **새 탭 `찬양주석`**(DB05 통합 문서)에만 저장 — 없으면 자동 생성.
- 곡 정보의 송폼은 기존과 같은 문자열(`V1-C-V2-C-B-C`)로 저장. 새 도구는 그 문자열을 만들어 줄 뿐입니다.
- 악보는 `/sheet/<Drive 파일 ID>` 로 스트리밍하되, **찬양악보 시트에 등록된 파일만** 열립니다(그 외 404).
- 권한: 소켓 접속 시 기존 토큰으로 인증(`찬양소켓인증_`). 필기 삭제는 본인 것만(편집 권한자는 전체).
- 예전 통계 팝업 코드는 그대로 두었고, 새 모듈이 없을 때만 예전 팝업으로 돌아갑니다(안전장치).

## 4. 배포
1. GitHub 에 올리기(`git push`) → Render 가 자동 배포(`npm install` 이 socket.io 를 설치).
2. Render 는 WebSocket 을 지원합니다. 추가 설정 없음. (Step 1 의 `scripts/db-setup.js` 수정본은 먼저 받아 두세요.)
3. 첫 실행 때 `찬양주석` 탭이 자동으로 만들어집니다.

## 5. 알아 둘 한계
- Render 무료 서버는 쉬었다 깨어나면 실시간 방 상태(리더 등)가 초기화됩니다. 팀 필기는 8초 안에 시트에 저장되고 종료 신호(SIGTERM) 때도 저장합니다.
- "나만 보기" 필기는 1.5초 뒤 서버(시트)에 저장되며, 계정 공유("팀 계정") 로그인이면 그 계정의 개인 필기는 함께 보입니다.
- 음성 큐는 브라우저 내장 음성을 씁니다. iPhone/iPad 는 무음 스위치가 켜져 있으면 소리가 안 납니다. 지연 보정은 기기별로 자동 측정.
- 가사 OCR 은 처음 쓸 때 라이브러리(tesseract.js)를 인터넷에서 받습니다.
- 리더 따라가기 스위치는 접속(세션)마다 기본 켜짐입니다.
- 구글 시트 쪽 코드는 가짜 구글(FakeGoogle)로 시험했고, 실제 구글 계정 연동은 배포 후 확인이 필요합니다.
