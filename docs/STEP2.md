## 3. 기존 기능은 어떻게 보존되나
- 기존 API · 시트 · 열 이름은 그대로. 새 데이터는 **새 탭 `찬양주석`**(DB05 통합 문서)에만 저장 — 없으면 자동 생성.
- 곡 정보의 송폼은 기존과 같은 문자열(`V1-C-V2-C-B-C`)로 저장. 새 도구는 그 문자열을 만들어 줄 뿐입니다.
- 악보는 `/sheet/<Drive 파일 ID>` 로 스트리밍하되, **찬양악보 시트에 등록된 파일만** 열립니다(그 외 404).
- 권한: 소켓 접속 시 기존 토큰으로 인증(`찬양소켓인증_`). 필기 삭제는 본인 것만(편집 권한자는 전체).
- 예전 통계 팝업 코드는 그대로 두었고, 새 모듈이 없을 때만 예전 팝업으로 돌아갑니다(안전장치).

## 4. 배포
1. GitHub 에 올리기(`git push`) → Render 가 자동 배포(`npm install` 이 socket.io 를 설치).
2. Render 는 WebSocket 을 지원합니다. 추가 설정 없음. (Step 1 의 `scripts/db-setup.js` 수정본은 먼저 받아 두세요.)
3. 첫 실행 때 `찬양주석` 탭이 자동으로 만들어집니다.

## 5. 알아 둘 한계
- Render 무료 서버는 쉬었다 깨어나면 실시간 방 상태(리더 등)가 초기화됩니다. 팀 필기는 8초 안에 시트에 저장되고 종료 신호(SIGTERM) 때도 저장합니다.
- "나만 보기" 필기는 1.5초 뒤 서버(시트)에 저장되며, 계정 공유("팀 계정") 로그인이면 그 계정의 개인 필기는 함께 보입니다.
- 음성 큐는 브라우저 내장 음성을 씁니다. iPhone/iPad 는 무음 스위치가 켜져 있으면 소리가 안 납니다. 지연 보정은 기기별로 자동 측정.
- 가사 OCR 은 처음 쓸 때 라이브러리(tesseract.js)를 인터넷에서 받습니다.
- 리더 따라가기 스위치는 접속(세션)마다 기본 켜짐입니다.
- 구글 시트 쪽 코드는 가짜 구글(FakeGoogle)로 시험했고, 실제 구글 계정 연동은 배포 후 확인이 필요합니다.

### 8-2. 소리는 보내지 않습니다 — 상태만 나눕니다
- 각 기기가 자기 Web Audio 로 딸깍을 냅니다. 서버가 나르는 것은 `{playing, bpm, num, den, marks, count, startAt, seq}` 뿐.
- `startAt` = 서버 시계 + 450ms. 모든 기기가 서버 시각 → 자기 오디오 시계로 바꿔 **같은 박에** 시작합니다(브라우저 시험: 기기 간 박 차이 60ms 이내).
- 강세만 바뀌면(`keep`) 시작 시각을 그대로 두어 박이 끊기지 않고, BPM · 박자 · 시작이 바뀌면 새 시작 시각으로 모두 다시 맞춥니다.

### 10-3. 알아 둘 한계
- **무음 모드**: iOS 는 버전마다 통하는 방법이 달라 ①②를 함께 씁니다. 시험 환경(크롬)에는 무음 스위치가 없어서 **호출이 실제로 일어나는지**(audioSession 값 · 소리 없는 오디오 재생 · 유효한 WAV)만 확인했습니다. **실제 아이폰 · 아이패드에서 무음 스위치를 켜고 한 번 확인**해 주세요. 소리 없는 오디오가 재생 중이면 아이폰 제어 센터에 "메트로놈"이 재생 중으로 보이는 것이 정상입니다.
- **화면 켜짐**: Wake Lock 은 화면이 보이는 동안만 유지됩니다(브라우저 규칙). 기기의 저전력 모드에서는 거절될 수 있어 그때는 동영상 방식이 대신합니다. 예비 동영상은 mp4 · webm 을 코드에 넣은 것이라 별도 파일이 없습니다. 크롬으로 두 방식 모두 검증(모의 Wake Lock · 실제 <video> 재생).
- **송폼 라벨**: 예전에 그려 둔 박스는 사라지는 것이 아니라 박스만 안 보이고 글자만 남습니다(데이터 그대로). 박스 모양을 다시 쓰려면 이전 버전으로 돌려야 합니다.
- **쪽 그림 저장소**는 메모리에만 있고(디스크 저장 없음) 화면을 닫으면 사라집니다. 아주 큰 쪽(폰 22MB · 컴퓨터 40MB 초과)은 저장하지 않습니다.
- 빠른 버튼은 악보 위쪽 모서리를 조금 가립니다 — 거슬리면 패널의 "악보 화면 위에 메트로놈 시작 버튼 띄우기"를 끄세요(패널의 고정 시작 버튼은 그대로 있습니다).
- 브라우저 시험은 크롬(Playwright) 기준입니다. 사파리(아이폰 · 아이패드)의 Wake Lock · audioSession 동작은 위 이유로 실기기 확인이 필요합니다.
